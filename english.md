# How to write Git commits ![github](https://www.readmecodegen.com/api/social-icon?name=github&size=35)
 
This guide helps you understand how to write commit messages in a clear, tidy way without losing your mind. If you follow these rules, your code will be much easier to understand for others too.
 
## The basic structure
 
Every commit should be written like this:
 
type(part_of_the_code): what the commit does
 
### The most important types to use
* feat: when you add a new feature (e.g., a new page or a new button).
* fix: when you fix an error or a bug that wasn't working.
* docs: when you only change texts, guides, or this README file.
* style: when you only change formatting, white space, or graphics but the code does the exact same things.
* refactor: when you rewrite the code to make it cleaner, without adding features.
* chore: when you update packages, libraries, or configure project files.

## Easy examples
 
* feat(login): added password check
* fix(api): fixed the data loading issue
* docs(readme): updated the commit guide
