# Jak pisać commity w Git ![github](https://www.readmecodegen.com/api/social-icon?name=github&size=35)
 
Ten poradnik pomaga zrozumieć, jak pisać wiadomości commitów w jasny, uporządkowany sposób i bez zawrotów głowy. Jeśli będziesz trzymać się tych zasad, Twój kod będzie o wiele łatwiejszy do zrozumienia również dla innych.
 
## Podstawowa struktura
 
Każdy commit powinien wyglądać tak:
 
typ(część_kodu): co robi commit
 
### Najważniejsze typy do użycia
* feat: kiedy dodajesz nową funkcję (np. nową stronę lub nowy przycisk).
* fix: kiedy naprawiasz błąd lub buga, który nie działał.
* docs: kiedy zmieniasz tylko teksty, poradniki lub ten plik README.
* style: kiedy zmieniasz tylko formatowanie, białe znaki lub wygląd, ale kod robi dokładnie to samo.
* refactor: kiedy przepisujesz kod, aby był czystszy, bez dodawania nowych funkcji.
* chore: kiedy aktualizujesz pakiety, biblioteki lub konfigurujesz pliki projektu.

## Proste przykłady
 
* feat(login): dodano sprawdzanie hasła
* fix(api): naprawiono problem z ładowaniem danych
* docs(readme): zaktualizowano poradnik commitów
