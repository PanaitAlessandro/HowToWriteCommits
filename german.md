# Wie man Git-Commits schreibt ![github](https://www.readmecodegen.com/api/social-icon?name=github&size=35)
 
Diese Anleitung hilft dir zu verstehen, wie man Commit-Nachrichten klar, ordentlich und ohne durchzudrehen schreibt. Wenn du diese Regeln befolgst, wird dein Code auch für andere viel leichter zu verstehen sein.
 
## Die Grundstruktur
 
Jeder Commit sollte so geschrieben werden:
 
Typ(Bereich_des_Codes): Was der Commit macht
 
### Die wichtigsten Typen, die man nutzen sollte
* feat: wenn du eine neue Funktion hinzufügst (z. B. eine neue Seite oder einen neuen Button).
* fix: wenn du einen Fehler oder Bug korrigierst, der nicht funktioniert hat.
* docs: wenn du nur Texte, Anleitungen oder diese README-Datei änderst.
* style: wenn du nur die Formatierung, Leerzeichen oder das Design änderst, aber der Code genau das Gleiche tut.
* refactor: wenn du den Code umschreibst, um ihn sauberer zu machen, ohne neue Funktionen hinzuzufügen.
* chore: wenn du Pakete oder Bibliotheken aktualisierst oder Projektdateien konfigurierst.

## Einfache Beispiele
 
* feat(login): Passwortprüfung hinzugefügt
* fix(api): Problem beim Laden der Daten behoben
* docs(readme): Commit-Anleitung aktualisiert
