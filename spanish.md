# Cómo escribir los commits en Git ![github](https://www.readmecodegen.com/api/social-icon?name=github&size=35)
 
Esta guía sirve para entender cómo escribir los mensajes de los commits de forma clara, ordenada y sin volverse loco. Si sigues estas reglas, tu código será mucho más fácil de entender también para los demás.
 
## La estructura básica
 
Cada commit debería escribirse así:
 
tipo(parte_del_código): qué hace el commit
 
### Los tipos más importantes para usar
* feat: cuando añades una nueva función (por ejemplo, una página nueva o un botón nuevo).
* fix: cuando arreglas un error o un bug que no funcionaba.
* docs: cuando cambias solo los textos, las guías o este archivo README.
* style: cuando cambias solo el formato, el espacio en blanco o el diseño pero el código hace lo mismo.
* refactor: cuando reescribes el código para hacerlo más limpio, sin añadir funciones.
* chore: cuando actualizas los paquetes, las librerías o configuras los archivos del proyecto.

## Ejemplos fáciles
 
* feat(login): añadido control de contraseña
* fix(api): solucionado el problema de carga de datos
* docs(readme): actualizada la guía de commits
