# Hoe je Git-commits schrijft ![github](https://www.readmecodegen.com/api/social-icon?name=github&size=35)
 
Deze gids helpt je te begrijpen hoe je commit-berichten duidelijk, netjes en zonder gek te worden schrijft. Als je deze regels volgt, is je code ook voor anderen veel makkelijker te begrijpen.
 
## De basisstructuur
 
Elke commit moet er zo uitzien:
 
type(deel_van_de_code): wat de commit doet
 
### De belangrijkste types om te gebruiken
* feat: als je een nieuwe functie toevoegt (bijv. een nieuwe pagina of een nieuwe knop).
* fix: als je een fout of bug oplost die niet werkte.
* docs: if alleen teksten, handleidingen of dit README-bestand aanpast.
* style: als je alleen de opmaak, witruimte of styling aanpast maar de code precies hetzelfde doet.
* refactor: als je de code herschrijft om deze netter te maken, zonder nieuwe functies toe te voegen.
* chore: als je pakketten of bibliotheken bijwerkt of projectbestanden configureert.

## Makkelijke voorbeelden
 
* feat(login): wachtwoordcontrole toegevoegd
* fix(api): probleem met laden van gegevens opgelost
* docs(readme): commit-handleiding bijgewerkt
