# Come scrivere i commit su Git ![github](https://www.readmecodegen.com/api/social-icon?name=github&size=35)
 
Questa guida serve a capire come scrivere i messaggi dei commit in modo chiaro, ordinato e senza impazzire. Se segui queste regole, il tuo codice sara molto piu facile da capire anche per gli altri.
 
## La struttura base
 
Ogni commit dovrebbe essere scritto cosi:
 
tipo(parte_del_codice): cosa fa il commit
 
### I tipi piu importanti da usare
* feat: quando aggiungi una nuova funzione (es. una nuova pagina o un nuovo bottone).
* fix: quando sistemi un errore o un bug che non funzionava.
* docs: quando cambi solo i testi, le guide o questo file README.
* style: quando cambi solo la formattazione, lo spazio bianco o la grafica ma il codice fa le stesse cose.
* refactor: quando riscrivi il codice per farlo piu pulito, senza aggiungere funzioni.
* chore: quando aggiorni i pacchetti, le librerie o configuri i file del progetto.

## Esempi facili
 
* feat(login): aggiunto controllo sulla password
* fix(api): sistemato il problema del caricamento dati
* docs(readme): aggiornata la guida ai commit
