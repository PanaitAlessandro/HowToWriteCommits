# Como escrever commits no Git ![github](https://www.readmecodegen.com/api/social-icon?name=github&size=35)
 
Este guia serve para entender como escrever as mensagens dos commits de forma clara, organizada e sem ficar maluco. Se seguires estas regras, o teu código será muito mais fácil de entender também para os outros.
 
## A estrutura básica
 
Cada commit deve ser escrito assim:
 
tipo(parte_do_código): o que o commit faz
 
### Os tipos mais importantes para usar
* feat: quando adicionas uma nova função (por exemplo, uma página nova ou um botão novo).
* fix: quando corriges um erro ou um bug que não estava a funcionar.
* docs: quando mudas apenas os textos, os guias ou este ficheiro README.
* style: quando mudas apenas a formatação, o espaço em branco ou o visual, mas o código faz a mesma coisa.
* refactor: quando reescreves o código para o deixar mais limpo, sem adicionar funções.
* chore: quando atualizas os pacotes, os ficheiros ou configuras os ficheiros do projeto.

## Exemplos fáceis
 
* feat(login): adicionada verificação de palavra-passe
* fix(api): resolvido o problema de carregamento de dados
* docs(readme): atualizado o guia de commits
